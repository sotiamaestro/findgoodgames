# DECISIONS.md

Calls made while building, in the order they came up. Each one was settled by testing rather than by asking; the evidence is in `pipeline/PROBE.md`, `pipeline/samples/` or the pipeline logs.

## Data sources

1. **GeForce NOW support comes from NVIDIA's catalog API, not the static JSON in the brief.** `static.nvidiagrid.net/.../gfnpc-en-US.json` still returns HTTP 200, but its `last-modified` is 29 March 2022 and it lacks every title added since (Palworld, PEAK, Lethal Company). The GeForce NOW website reads `POST https://api-prod.nvidia.com/services/gfngames/v1/gameList` (raw GraphQL body, no key). It returns 6,110 Steam appids with a per-region status when a valid `vpcId` is passed (`NP-SJC6-04`; US regions returned identical lists). A game counts as supported when its Steam variant has a status other than UNKNOWN; AVAILABLE, PATCHING and SERVER_MAINTENANCE all count, since the last two are temporary. The pipeline refuses a pull that returns fewer than 1,000 Steam ids and falls back to the previous cached list, so a half-broken NVIDIA response cannot blank the GeForce NOW column.
2. **`optimized` is null for every game.** The current NVIDIA API has no "optimized" or "fully optimized" field (checked by probing field names; the schema rejects `isFullyOptimized`, `optimized`, `isOptimized`, `optimizedStatus`, `rtx`, `dlss`, `tier`). The stale static file was the only place that flag existed. The dataset keeps the field so it can be filled in later without a schema change.
3. **NVIDIA's edge stalls any request whose User-Agent contains "github.com".** A UA with a URL in it hangs until timeout; the same request with a plain product token answers in 300 ms. The pipeline UA is therefore `coop-finder-pipeline/0.1 (open-source co-op game finder; weekly data refresh)` with no URL or email in it.
4. **Candidates come from Steam's own tag query, with SteamSpy and `data/picks.json` as extra seeds.** SteamSpy's `request=tag` endpoint returns only its top slice: 798 games for Co-op, 508 for Online Co-Op, 193 for Local Co-Op, 895 distinct. `IStoreQueryService/Query` with `tagids_must_match` returns every game carrying the tags (18,658 for the union of Co-op, Online Co-Op, Local Co-Op, Co-op Campaign, Split Screen, 4 Player Local and Local Multiplayer) and includes the full store record in the same response, 500 per page, no key. That makes the "store data" stage about 40 requests instead of thousands of `appdetails` calls, and it is also why there is no store-details cache with a 30-day TTL: a full run simply refetches everything (which also satisfies "refetch Early Access games on every full run"). SteamSpy is still pulled on full runs (three requests, one per minute) and merged in; if it fails the run continues without it.
5. **The review prefilter uses Steam's own summary, not SteamSpy's counts.** Stage 1 of the funnel ("fewer than 100 reviews by SteamSpy's count") exists to avoid wasting store requests. With the Query endpoint the store summary is free, so the 100-review cut uses `reviews.summary_filtered.review_count` from Steam, which is exact. SteamSpy counts are only used to decide which SteamSpy-only games are worth a GetItems call.
6. **Exact review totals come from `GetAppReviews` with `purchase_type=0` (Steam purchases) and `languages=["all"]`.** That is the combination that reproduces the number on the store page ("Total reviews in all languages: 393,028" for Portal 2; the API gave 392,793 a few minutes earlier, GetItems' summary 392,971). `purchase_type=1` (All) adds key activations and is about 20% higher. The `language` parameter from the old endpoint is silently ignored; the new one is `languages` (array). The old `store.steampowered.com/appreviews` endpoint redirects and is not used.
7. **Games that cannot pass the 70% bar on the store summary skip the review request.** `percent_positive` is an integer, so a game showing 68% or lower cannot be 70%+; 69% might be (69.5% rounds up) and is still fetched. This saved 657 of 2,996 requests on the first full run. If the review call fails for a game after the 5-minute back-offs, the pipeline keeps the game using the summary-derived split (count x percent) and marks it as not exact.
8. **Steam's displayed percentage is kept as `pct`.** When GetAppReviews succeeds, `pos`/`neg` are exact and `pct` is Steam's own rounded percentage from the summary, so the card shows the same number as the store page even when a game sits on a rounding boundary. `wilson` and `value` use the exact counts.
9. **PCGamingWiki is read through wikitext, not Cargo.** `action=cargoquery` answers "You don't have permission to run arbitrary Cargo queries" for anonymous callers, `Special:CargoExport` is behind a browser challenge, and the `Infobox_game` table no longer exists. The MediaWiki API still serves page content: up to 50 titles per `prop=revisions` request, matched to Steam by the infobox's `steam appid` and `steam appid side` lines, then `{{Network/Multiplayer}}` is parsed for `local play players`, `lan play players` and `online play players`. Titles that do not resolve get one `list=search` text query for the appid (the only search mode PCGamingWiki supports; OR and `insource:` are not available there). Misses are cached for 30 days like hits. Modes marked `hackable` do not count; `true` and `limited` do.
10. **Player counts ship as `{ online, local }`.** LAN counts are parsed but not shipped, because the party-size filter compares against online or local counts only. On the first dev sample, 76% of games had a PCGamingWiki page and 43% had at least one count.
11. **Co-op mode mapping.** `online` = category 38 Online Co-op, `local` = 39 Shared/Split Screen Co-op, `lan` = 48 LAN Co-op, `rpt` = 44 Remote Play Together. `split` = local plus the community tag "Split Screen" (10816), because Steam's categories do not separate split screen from shared screen. A game with only the generic category 9 "Co-op" and none of 38/39/48 is treated as online co-op (240 of 2,996 games on the first full run); these are mostly older titles whose store page predates the detailed categories.
12. **Early Access and MMO flags.** `ea` comes from GetItems' `is_early_access`; `leftEaAt` prefers Steam's own `release_from_early_access_date` and otherwise the date the pipeline first saw the switch (kept in `cache.json` history). `mmo` is category 20 and drives the "Hide MMOs" filter; MMOs are kept in the dataset because the toggle can show them.
13. **Capsule art always comes from the asset field.** `assets.library_capsule` sometimes lives under a hashed sub-path (`3dee.../library_capsule.jpg`) and the guessed `library_600x900.jpg` path 404s for some new games (PEAK), so `cap` is built from `asset_url_format` and never guessed. 100% of games on the probed page had the field. The UI falls back to the header image, center-cropped, if the capsule fails to load.
14. **No Steam API key is needed.** Every endpoint used (GetItems, Query, GetAppReviews, GetStoreCategories, GetTagList, appdetails, storesearch) answered without one. `STEAM_API_KEY` is passed through when present and documented as optional.
15a. **Games with no purchase option that are not free to play are dropped.** Nine delisted or bundle-only titles (FIFA 22, F1 24, WWE 2K24, Divinity: Original Sin Classic, Path of Exile 2 and others) came through the first full run with `best_purchase_option` missing, which the first version of the pipeline rendered as $0 "Free". They now count as "not purchasable" in stage 2, and the daily price run removes a game that loses its purchase option.
15b. **Blurbs fall back to `appdetails`.** 42 older store pages (Left 4 Dead, Arma 2, AudioSurf and others) have no `short_description` in GetItems. Those games get one `appdetails?filters=basic` call on the store queue, cached for 30 days.
15. **Type filter.** GetItems' `type` is 0 for games, 2 for tools, 4 for DLC, 11 for music; the Query endpoint's `include_games` already returns only type 0. `type == 0` is the "type == game" check.

## Scoring and content

16. **PRICE_WEIGHT is 0.5, not 0.75.** On the first full run (202 games in the default view) a weight of 0.75 left no game over $10 in the top 30 and put PlateUp!, Don't Starve Together and Ultimate Chicken Horse at positions 82, 61 and 54. The brief's own calibration sentence ("a $5 game at about 89% ranks near a $20 game at about 97%") solves to a weight of (97 - 89) / (20 - 5) = 0.53; at 0.5 those two games tie within half a point, three games over $10 reach the top 30, and the top 10 is unchanged in spirit (Vampire Survivors, Brotato, Portal 2, PEAK, Left 4 Dead 2, Terraria). Full position tables for 0.4, 0.5, 0.6, 0.75 and 1.0 are in the Tuning section at the bottom.
17. **Tags stored per game: the top 8 by weight, minus mode and state tags** (Co-op, Online Co-Op, Local Co-Op, Co-op Campaign, Split Screen, 4 Player Local, Local Multiplayer, Multiplayer, Singleplayer, Early Access, Free to Play, Massively Multiplayer). Those facts live in `coop`, `ea`, `price.free` and `mmo` already; keeping them as tags would make "Co-op" the most common filter tag, which is useless here. The UI offers the 40 most common remaining tags.
18. **Blurbs are Steam's `short_description`, entity-decoded, cut at 160 characters on a word boundary.** Em and en dashes inside them are replaced with plain dashes so Steam's own copy follows the same rule as the site copy.
19. **Review cache TTL is 20 hours, not "every run".** The brief asks for review totals to be refetched on every full run. They are, because full runs are a week apart. The 20-hour TTL exists so that a run that crashes and is restarted the same day resumes instead of re-sending 2,000 requests; the cache is written every 50 apps for the same reason.

## Frontend

19a. **Three fields were added to the brief's `Game` type: `mmo` (category 20, for the Hide MMOs filter), `best` (the `best` string from picks.json, shown on the Crew Picks card) and `pickRank` (the game's position in picks.json).** Everything else matches the brief's schema exactly.
19b. **The Crew Picks row keeps the order of picks.json, not value order.** Two reasons: a curated list reads as curated when its order is deliberate (and the owner can reorder the file), and the first card in that row is the page's largest contentful paint. When the row was value-sorted, a price change between the bundled snapshot and the live file moved a different game into the first slot after the swap, which pushed Lighthouse's LCP from 3.3 s to 6.2 s. With file order the first card only changes when picks.json changes, which is also when the snapshot is rebuilt.

20a. **Card art opens the Steam store page in a new tab; card text opens the detail sheet.** The brief says a card click opens the store page and that a detail view exists as a side sheet, so the two targets are split by area: the poster is a plain link to `store.steampowered.com/app/<id>` (new tab, works with middle-click and long-press), the name and facts under it open the detail sheet, and the detail sheet carries the secondary `steam://store/<id>` button. Row posters and the editorial card follow the same split.
20. **Grid cards carry text; row cards are posters only.** The reference grid is posters alone, but the brief lists ten facts per card. Cards in the main grid are 2 columns wide on phones with dense metadata under the art; the horizontal rows (Crew Picks, Hidden Gems, On Sale Now, Just Left Early Access) use poster-only cards with a one-line caption, like Letterboxd's list strips.
21. **Filter state is in the query string with short keys, and only non-default values are written**, so the bare URL is the default view and a copied link is short. Opening a game (`g=`), the shortlist (`view=shortlist`) and Check a game (`check=`) push history entries so the back button closes them; filter changes replace the entry.
22. **Party size compares against `players.online` unless only local modes are selected or "1 copy is enough" is on**, in which case it uses `players.local`. Games without a count stay visible with a "? players" chip unless "Confirmed player count only" is on. "8+" means at least 8.
23. **Tags filter with AND semantics** (each selected tag must be present); co-op modes filter with OR (any selected mode).
24. **"On Sale Now" and "Just Left Early Access" rows require 200+ reviews**, so a discounted game nobody has played does not lead the page. Hidden Gems uses the brief's exact rule (90%+, 200-5,000 reviews, $15 or less). Every row applies the current GeForce NOW, Early Access, price and MMO settings.
25. **Check a game looks in the dataset first, then asks the Netlify function.** A pasted URL or appid goes straight to a verdict. A name shows dataset matches first (instant) with a "search all of Steam" row that calls `/api/check-game?q=` (storesearch) and then `/api/check-game?appid=` for the chosen result. The function runs GetItems and the GeForce NOW id list in parallel with 8-second budgets and falls back to `appdetails` if GetItems fails. A game with no co-op category gets the plain "No co-op" headline.
26. **The function reads `gfn-steam.json` from jsDelivr with a raw.githubusercontent fallback and caches it in the warm instance for 6 hours.** If both fail it still answers, with `gfn: false` and `gfnListUnavailable: true`.
27. **Fonts are self-hosted Latin subsets built with fonttools.** Schibsted Grotesk ships `tnum`, so no font switch was needed; Newsreader is instanced to wght 400-700 and opsz 18-72 before subsetting. Italics are not shipped.
28. **Desktop reuses the phone system.** The filter sheet becomes a sticky left rail with the same rows (accordion controls), the grid widens to 5-8 columns, and detail / check / pick open as a right side sheet.

31. **The build inlines an above-the-fold bootstrap into index.html.** With the real dataset (1.7 MB raw, about 330 KB over the wire) Lighthouse's mobile simulation put the largest contentful paint at 6.4 s and the performance score at 77, because the first poster could not be requested until the JSON had arrived and rendered. The Vite build now reads the bundled snapshot and inlines the games the default home view paints above the fold (12 per row plus the first 36 of the grid, 55 games, about 16 KB gzipped) as a JSON script tag, and preloads the first Crew Picks image. The app renders from that immediately and swaps in the live file when it arrives; counts, tag options and the footer date wait for the live file so nothing stale is shown as a fact. The bootstrap is only used when the URL is the default view (no filters, no game, no check), so a shared link never shows a subset. games.json itself is unchanged and still carries every field in the brief's schema.
32. **GeForce NOW's catalog includes "Install-to-Play" titles.** NVIDIA's games page says premium members get 2,200+ Install-to-Play games on top of the Ready-to-Play library; the catalog API does not expose which is which (no field name we tried validates), so `gfn.ok` means "in NVIDIA's GeForce NOW library", which may require the Ultimate or Performance tier and an install step for some titles. The spot checks (Brotato, Flock Around, PEAK present; WEBFISHING absent) matched the public search.

33. **The browser revalidates games.json in the background after the first load, against GitHub's raw file.** jsDelivr answers with `cache-control: public, max-age=604800`, so a returning visitor would otherwise keep last week's file for seven days, and during testing one jsDelivr edge kept serving the pre-purge file after another already had the new one. The first fetch uses the normal cache for speed; a second `no-cache` fetch of `raw.githubusercontent.com` (five-minute cache) swaps in the newer file when `generatedAt` differs.
34. **The data file is fetched only after the first poster has loaded when the bootstrap is on screen.** Lighthouse's mobile simulation was bimodal (77 or 97) depending on whether the 330 KB JSON or the 58 KB LCP image won the simulated bandwidth first. Starting the JSON on the image's load event (or after 700 ms, whichever comes first) makes the order deterministic and costs well under a second of data freshness on the first visit.

## Deployment

29. **Netlify is a manual step for the owner.** `gh` was logged in, so the repository, the data branch and the workflow were set up from here. The Netlify CLI was not installed or logged in and signing in needs the owner's browser session, so connecting the site is documented in README.md step 2 instead.
30. **The bundled fallback snapshot is refreshed by hand** (`npm run data -- --fallback` or copying `.data/games.json`), never by the workflow, so data refreshes never touch `main` and never trigger a Netlify build.
